Dari server ke layar

Halaman web tidak disimpan di HP-mu. Berkasnya diambil dari server, lalu digambar browser. Kenali perjalanan singkatnya.

Browser meminta, server menjawab

Saat kamu membuka website dari internet, berkasnya tidak tersimpan di HP atau laptopmu. Berkas itu ada di server, komputer yang menyala terus dan tersambung ke internet. Browser meminta berkas kepada server, lalu menggambar hasilnya di layar.

  1. Kamu mengetik alamat atau mengeklik sebuah tautan.
  2. Browser mengirim permintaan ke server lewat HTTP atau HTTPS.
  3. Server membalas dengan berkas HTML, lalu CSS, JavaScript, dan gambar yang dipakai halaman itu.
  4. Browser membaca HTML dari atas ke bawah dan menampilkan isinya.

Dalam hubungan ini, browser disebut client — pihak yang meminta — dan server adalah pihak yang menjawab.

Setelah berkas sampai, browser membaca HTML, menyusun elemennya, memuat CSS dan gambar, lalu menggambar hasilnya di layar. Proses ini disebut render.

Karena harus menempuh perjalanan ini, halaman bisa terasa lambat saat pertama dibuka. Berkas yang lebih kecil dan gambar yang tidak terlalu besar membuat halaman lebih cepat sampai dan dirender.

Alamat punya bagian

Alamat web terdiri dari tiga bagian. Kamu tidak perlu menghafalnya sekarang, tetapi mengenalnya membantu saat membaca tautan.

  • https:// — protokol, cara browser berbicara dengan server. HTTPS adalah versi terenkripsi dari HTTP.
  • sekolahku.sch.id — domain, nama website yang kamu tuju.
  • /profil/rani.html — path, halaman tertentu yang diminta dari website itu.

Ketiganya dibaca berurutan. Contoh lengkap: https://sekolahku.sch.id/profil/rani.html.

Domain, hosting, dan DNS

Tiga hal ini menjelaskan bagaimana alamat yang kamu ketik bisa menemukan halaman yang benar.

  • Domain — nama website yang disewa, misalnya webiko.my.id. Nama ini yang kamu ketik dan ingat.
  • DNS — sistem yang menerjemahkan domain menjadi alamat IP server. Ibarat buku telepon: kamu mengetik nama, DNS memberi nomor tujuan.
  • Hosting — tempat berkas website disimpan di server. Bisa server milik sendiri atau layanan sewa.

Domain dan hosting dipisah supaya kamu bisa pindah server tanpa mengganti nama website. Cukup arahkan domain ke server baru lewat DNS.

Rangkuman

  • Browser adalah client yang meminta; server adalah pihak yang menjawab.
  • Permintaan dan balasan berjalan lewat HTTP atau HTTPS. HTTPS menambahkan enkripsi.
  • Browser menyusun elemen, memuat CSS dan gambar, lalu merender halaman.
  • Alamat web terdiri dari protokol, domain, dan path.
  • DNS menerjemahkan domain ke alamat IP server. Domain adalah namanya, hosting adalah tempat berkasnya.
