Membaca pesan error

Error bukan tanda kodemu buruk. Error adalah petunjuk: JavaScript memberi tahu apa yang salah dan di baris mana. Semakin tenang membacanya, semakin cepat masalahnya ketemu.

Tiga bagian pesan error

Pesan di konsol biasanya punya nama, keterangan, dan lokasi. Nama menunjukkan jenis masalah, keterangan menjelaskan penyebabnya, dan baris at pertama menunjuk berkas serta nomor baris kesalahan.

Konsol error 
Uncaught TypeError: Cannot read properties of null    at tampil.js:4

TypeError adalah namanya, Cannot read properties of null adalah keterangannya, dan tampil.js:4 menunjukkan lokasi. Teks aslinya bisa berbeda menurut browser.

Yang sering muncul di konsol

  • ReferenceError — nama variabel salah ketik atau belum dibuat. Contoh: tidakAda is not defined.
  • TypeError — nilai tidak seperti yang dibayangkan. Contoh: memakai null seolah objek, atau memanggil sesuatu yang bukan fungsi.
  • SyntaxError — kode tidak bisa dibaca sejak awal, misalnya kurung kurawal kurang atau tanda kutip tidak ditutup.
  • 404 — status dari server, bukan error JavaScript. fetch tidak melempar error; periksa res.ok.
  • Failed to fetch — jaringan putus atau alamat tidak bisa dihubungi. Ini TypeError dan ditangani .catch.

try dan catch

try berisi kode yang mungkin gagal. catch menerima error itu sebagai objek, lalu memutuskan apa yang ditampilkan. Tanpa catch, error menghentikan sisa kode.

tangkap.js JS 
try {  const data = JSON.parse("bukan json");  console.log(data);} catch (galat) {  console.log(galat.name);  console.log(galat.message);}

galat.name berisi nama jenisnya, galat.message berisi keterangannya. Menulis galat langsung ke halaman menghasilkan <nama>: <pesan>, misalnya TypeError: ...; objek biasa bisa menjadi [object Object].

Melempar error sendiri

Kadang data tidak salah secara JavaScript, tetapi tidak masuk akal untuk program: nilai kosong, angka negatif, atau isian yang belum lengkap. throw new Error(...) menghentikan alur normal dan melempar masalah ke catch terdekat.

bagi.js JS 
function bagi(a, b) {  if (b === 0) {    throw new Error("Tidak bisa dibagi nol");  }  return a / b;}try {  console.log(bagi(10, 0));} catch (galat) {  console.log(galat.message);}

Pesannya buatan sendiri, jadi bisa ditulis dalam bahasa yang dimengerti pengguna.

Error yang datang belakangan

try/catch hanya menangkap error di alur yang sama. Kode di dalam .then berjalan nanti, setelah try selesai. Untuk permintaan server, tangkap kegagalannya dengan .catch.

ambil.js JS 
fetch("/data/contoh-kelas.json")  .then(function (res) {    return res.json();  })  .catch(function (galat) {    console.log(galat.message);  });

try/catch di sekitar fetch tidak menangkap kegagalan di dalam .then. Rantai Promise punya .catch sendiri.

Jangan menelan error

catch (galat) {} yang kosong membuat error hilang tanpa jejak. Halaman tetap diam, padahal ada yang salah. Tampilkan pesannya, catat dengan console.error, atau beri tahu pengguna dengan kalimat yang jelas.

Latihan langsung

Tangkap dan baca error

Kode berjalan di pratinjau. Kesalahan di dalam try ditangkap catch, lalu nama dan pesannya ditulis ke halaman.

  1. Klik Jalankan. Pratinjau menampilkan TypeError: Cannot read properties of null (reading 'nama').
  2. Ganti null dengan { nama: "Ayu" }, lalu jalankan. Pratinjau menampilkan Ayu.
  3. Ganti dua baris di dalam try dengan throw new Error("Data kosong");, lalu jalankan. Muncul Error: Data kosong.
  4. Ganti galat.name + ": " + galat.message menjadi galat.message, lalu jalankan. Hanya keterangannya yang tampil.
  5. Kembalikan kode awal.

Pratinjau halaman

Klik Jalankan untuk melihat hasil.

Cek hasil:

  • Data null → TypeError: Cannot read properties of null (reading 'nama').
  • Data Ayu → teks Ayu, tanpa error.
  • Error buatan sendiri → Error: Data kosong.
  • Hanya galat.message → keterangan tanpa nama jenisnya.

Kesalahan umum

  • Menulis catch (galat) {} kosong, sehingga error hilang dan masalah tidak pernah ketahuan.
  • Membaca galat.name saja tanpa galat.message, sehingga keterangan penyebabnya hilang.
  • Mengira try/catch menangkap error di dalam .then. Pakai .catch pada rantai Promise.
  • Menangkap semua error tanpa memeriksa jenisnya, lalu memberi pesan yang menyesatkan.
  • Berharap try/catch menolong SyntaxError. Kode yang tidak bisa dibaca tidak pernah berjalan.
  • Mengabaikan lokasi berkas dan nomor baris di baris at.

Rangkuman

  • Error memberi nama, keterangan, dan lokasi masalah.
  • ReferenceError, TypeError, dan SyntaxError sering muncul saat belajar.
  • try/catch menangkap error di alur yang sama; galat.message berisi keterangannya.
  • throw new Error("...") dipakai untuk menandai data yang tidak masuk akal.
  • Error di dalam .then ditangani .catch.
  • Jangan menelan error; tampilkan atau catat pesannya.
